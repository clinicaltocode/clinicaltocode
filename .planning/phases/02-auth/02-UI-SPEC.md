## Spacing Scale

Unchanged from Phase 1. All values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing, card padding inner |
| lg | 24px | Section padding, sidebar widget padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions (carried from Phase 1):
- Nav height: 72px (fixed layout dimension, not a spacing token)
- Touch targets: 48px minimum height for all interactive elements (accessibility floor)
- Content max-width: 1200px (layout constraint, not a spacing token)

### Approved Arbitrary Tailwind Values

All `[value]` syntax in this spec is pre-approved. No other arbitrary values may be added without updating this list.

| Value | Location | Justification |
|-------|----------|---------------|
| `py-[80px]` | Hero zone (carried from Phase 1) | 80px = 20 × 4; standard Tailwind scale has no `py-20` in v4 config |
| `max-w-[1200px]` | Content area (carried from Phase 1) | Layout constraint from `index.html`; no semantic token name for max-width |
| `bg-[#1a1a1a]` | Footer (carried from Phase 1) | Exact nav/footer color from `index.html` `:root` |
| `pt-[64px]` | Footer (carried from Phase 1) | 64px = 16 × 4; maps to `3xl` token but used inline for self-documentation |
| `pb-[32px]` | Footer (carried from Phase 1) | 32px = 8 × 4; maps to `xl` token but used inline for self-documentation |
| `mt-[80px]` | Footer (carried from Phase 1) | 80px = 20 × 4; above-spacing-scale but below page-level |
| `max-w-[400px]` | Auth form Card | 400px = 100 × 4; standard narrow form width; no semantic token name for form-width |
| `min-h-[48px]` | Input fields | 48px = 12 × 4; enforces accessibility touch target floor on text inputs |
| `text-[#666666]` | Footer links, helper text, sub-notes | Secondary text color from `index.html` `:root`; not a named @theme token (no semantic role needed at skeleton stage) |
| `text-[#1a1a1a]` | Confirm/verify-email body text | Primary text color from `index.html` `:root`; explicit override of shadcn's foreground token for prose readability |

## Copywriting Contract

### Tone Rules

Carried forward from Phase 1 without change.

| Rule | Specification |
|------|---------------|
| Voice | Professional and direct. Peer-to-peer, not vendor-to-customer. |
| Audience | Clinicians and healthcare IT professionals — assume domain knowledge, no over-explaining. |
| Sentence length | Short. Prefer one idea per sentence. |
| Reading level | Plain English. No jargon unless it is clinical/IT terminology the audience already uses. |
| Prohibited words | "revolutionary", "game-changer", "disrupting", "empower", "leverage", "seamless", "world-class", "cutting-edge", "innovative" |
| Numbers | Use numerals for counts and stats (e.g. "3 articles", not "three articles"). |

**Additional tone guidance for auth copy:**
- Do not punish the user for errors. Error messages state what happened, not what the user did wrong.
- Never distinguish between "wrong email" and "wrong password" in error messages (enumeration attack prevention).
- Verification copy sets clear expectations: what the user needs to do and why.

### CTA Formatting Rules

Carried forward from Phase 1.

- Primary CTA: Verb phrase, title case, ≤ 3 words. Examples: "Sign In", "Create Account".
- Secondary CTA: Verb phrase, title case, ≤ 4 words. Examples: "Join the Community".
- No exclamation marks on CTAs.
- No first-person possessive ("My Account" → "Your Account" or just "Account").

## Layout Contract

### `/auth/login` — Login Page

**Primary focal point:** "Sign in" heading and email input.

**Page structure:**
- Full-page centered layout (not the two-column article layout from Phase 1)
- Vertically and horizontally centered Card on a white background
- Nav is present (same sticky nav as Phase 1 — no auth-specific nav variant)
- No footer on auth pages (reduces visual clutter on single-purpose pages)

| Zone | Implementation |
|------|----------------|
| Page wrapper | `min-h-screen flex items-center justify-center bg-white px-4` |
| Card | shadcn Card, `max-w-[400px] w-full`, default border and shadow |
| Card header | `p-6 pb-0` — page title (h1, 32px/600) |
| Card content | `p-6` — form fields stacked vertically, `gap-4` between each Label+Input pair |
| Email field | Label ("Email address") + Input (type="email", name="email", placeholder "you@example.com"), full width |
| Password field | Label ("Password") + Input (type="password", name="password"), full width |
| Error zone | `<p role="alert" class="text-sm text-red-600">` below the password field, only rendered when error state is set |
| Submit button | shadcn Button, full width (`w-full`), primary variant, `min-h-[48px]`, text "Sign in" / "Signing in..." |
| Footer link | `text-sm text-[#666666]` centered below Card: "Don't have an account? [Create one](/auth/signup)" |

**Behavior:**
- Authenticated users visiting `/auth/login` are redirected to `/` by middleware.
- Form uses Server Action with `useActionState` (React 19) / `useFormState` (React 18) for inline error display.
- Error message replaces itself on each new submission attempt.
- Submit button is disabled during pending state via `useFormStatus`.

### `/auth/verify-email` — Email Verification Gate

**Primary focal point:** "Verify your email to continue" heading.

**Page structure:** Static-looking page with one interactive resend form. Centered single-column layout.

| Zone | Implementation |
|------|----------------|
| Page wrapper | `min-h-screen flex items-center justify-center bg-white px-4` |
| Content block | `max-w-[400px] w-full text-center flex flex-col gap-4` |
| Heading | h1, 32px/600: "Verify your email to continue" |
| Body | `text-base text-[#1a1a1a]`: explanation paragraph (see Copy Table) |
| Resend form | Plain `<form>` wrapping a single shadcn Button (outline variant, full width, `min-h-[48px]`): "Resend confirmation email" / "Sending..." |
| Status message | `<p role="status" class="text-sm">` — success: `text-secondary` (#00a86b); error: `text-red-600`; only rendered after resend attempt |
| Back link | `text-sm` anchor styled with `text-primary`: "Back to home" → `/` |

**Behavior:**
- Middleware redirects unverified authenticated users hitting `/forum/*` or `/profile/*` to this page.
- The resend form calls the `resendVerificationEmail` Server Action.
- The user's email is read from the active session via `supabase.auth.getUser()` inside the Server Action — no email field in the UI.
- If the user is not logged in (somehow lands here unauthenticated), the resend action returns an error; the page still renders without crashing.
- Resend button is disabled during pending state.
