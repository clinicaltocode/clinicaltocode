## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, tag gaps |
| md | 16px | Default element spacing, input padding |
| lg | 24px | Section padding, form field stacks |
| xl | 32px | Layout gaps, card padding |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing, footer padding |

Exceptions:
- Nav bar fixed at 72px height (established in `app/page.tsx`)
- Touch targets min-height 48px (established across all interactive elements)
- Ad slot containers: min-height 250px (300x250 IAB medium rectangle), min-width 300px — these are layout reservation values, not spacing tokens

Source: Established project patterns from `app/page.tsx`, `app/articles/[slug]/page.tsx`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.6 |
| Label / meta | 14px | 400 (regular) | 1.5 |
| Heading (section) | 20px | 600 (semibold) | 1.2 |
| Display (hero / page title) | 28px | 600 (semibold) | 1.2 |

Source: Derived from `app/globals.css` (body line-height: 1.6), `app/page.tsx` (text-sm for nav links = 14px, text-xl for hero sub = 20px, font-semibold consistently), `app/articles/[slug]/page.tsx` (text-3xl / md:text-5xl for article h1 — use 28px for non-hero headings).

Notes:
- Newsletter form fields and labels use 14px label / 16px input (consistent with existing Input component).
- Ad slot "Ad" label (accessibility disclosure) uses 12px, weight 400, color `--muted-foreground` (`oklch(0.556 0 0)`).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` / `var(--background)` | Page background, form surfaces, card backgrounds |
| Secondary (30%) | `oklch(0.97 0 0)` / `var(--muted)` | Ad slot placeholder background, email input container, section dividers |
| Accent (10%) | `#0066cc` / `var(--primary)` | Subscribe CTA button, link hover, newsletter heading, confirmation link text |
| Destructive | `oklch(0.577 0.245 27.325)` / `var(--destructive)` | Validation error on invalid email input |

Accent reserved for:
- The "Subscribe" submit button (newsletter form)
- "Confirm your subscription" link text in the confirmation email
- Any inline link pointing to the newsletter confirmation success page

Source: `app/globals.css` — `--primary: #0066cc`, `--muted: oklch(0.97 0 0)`, `--destructive: oklch(0.577 0.245 27.325)`. Pattern consistent with all prior phases.

Additional color notes:
- Ad slot placeholder (pre-activation): `background: var(--muted)` (`oklch(0.97 0 0)`), `border: 1px solid var(--border)` (`oklch(0.922 0 0)`), `border-radius: var(--radius)` (0.625rem). This prevents layout flash and looks intentional before AdSense activates.
- Ad slot placeholder text: "Advertisement" in 12px, `var(--muted-foreground)`, centered — required by AdSense policy and good UX practice.

## Layout Contracts

### Newsletter Signup Widget

Used on: homepage (`app/page.tsx` aside/sidebar area, replacing empty `<aside />`), and optionally as a standalone section below article body.

```
┌──────────────────────────────────────────────┐
│  Stay informed                               │  ← 20px semibold, color: #1a1a1a
│  Clinical insights and healthcare IT         │  ← 14px regular, color: #666666
│  perspectives, delivered to your inbox.      │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │ your@email.com                         │  │  ← Input component, full width
│  └────────────────────────────────────────┘  │
│  [        Subscribe        ]                 │  ← Button, variant="default", full width
│                                              │
│  (error message if invalid — 14px red)       │
└──────────────────────────────────────────────┘
```

- Container: `bg-white border border-[var(--border)] rounded-[var(--radius)] p-6` (24px padding)
- Gap between label and input: 16px
- Gap between input and button: 8px
- Max-width on homepage aside: 300px (matches existing `style={{ gridTemplateColumns: '1fr 300px' }}`)
- Full-width variant for article pages: `max-w-[720px] mx-auto`

### Ad Slot Container

Used on: article detail pages (after article body, before Forum CTA), homepage main content area, forum thread detail pages.

```
┌─────────────────────────────────────────────┐
│  Advertisement                              │  ← 12px, muted-foreground, text-center
│                                             │
│  [  muted background placeholder / ins  ]  │  ← min-height: 250px, min-width: 300px
│                                             │
└─────────────────────────────────────────────┘
```

- Outer wrapper: `min-h-[250px] min-w-[300px] bg-[var(--muted)] border border-[var(--border)] rounded-[var(--radius)] flex flex-col items-center justify-center`
- The `<ins>` element fills the wrapper: `display: block; width: 100%; height: 100%`
- The "Advertisement" label sits above the wrapper as a `<p>` — not inside it — so it does not contribute to CLS
- Article page placement: `<div className="max-w-[720px] mx-auto my-8">` — placed after `<ArticleBody>` and before the Forum CTA `<div>`
- Homepage placement: inside the `<aside>` in the existing `1fr 300px` grid, below the newsletter widget
- Forum thread page placement: below the first reply block, before the reply form

## Interaction States

### Newsletter Form

| State | Visual |
|-------|--------|
| Default | Input: `border-[var(--border)]`, placeholder text `#666666` |
| Focus | Input: `outline-ring/50` (inherited from globals.css `* { @apply outline-ring/50 }`) |
| Loading (submitting) | Button disabled, text "Subscribing...", spinner via `opacity-50 cursor-not-allowed` |
| Success | Form replaced with success message (heading + body copy from Copywriting Contract) |
| Error (invalid email) | Red border on input (`border-destructive`), error text below input in 14px `var(--destructive)` |
| Error (server) | Error text below button in 14px `var(--destructive)`, button re-enabled |
| Already subscribed | Success variant message (not an error — "You're already on the list.") |

### Ad Slot (pre-activation)

| State | Visual |
|-------|--------|
| Default (no AdSense ID) | Muted background placeholder visible — `NEXT_PUBLIC_ADSENSE_CLIENT_ID` env var not set, `<Script>` tag not rendered, `<ins>` not pushed |
| Active (AdSense ID present) | Google fills the `<ins>` element; CSS `min-height` prevents CLS |

## Accessibility Contracts

- Email input `id="newsletter-email"`, `<label htmlFor="newsletter-email">` with visible text "Email address"
- Subscribe button `aria-busy="true"` during loading state
- Success message container uses `role="status"` so screen readers announce it without focus move
- Error messages use `role="alert"` for immediate announcement
- Ad slot wrapper has `aria-label="Advertisement"` on the outer `<div>`
- All interactive elements maintain `min-h-[48px]` touch target (established project pattern)
