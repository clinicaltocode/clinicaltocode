## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge internal padding, report button icon-text gap |
| sm | 8px | Form field gap, table cell internal padding, inline action gap |
| md | 16px | Card internal padding, modal padding, form row spacing |
| lg | 24px | Section padding, admin page content padding |
| xl | 32px | Admin layout main content padding, modal max-width gutter |
| 2xl | 48px | Major section breaks on community guidelines page |
| 3xl | 64px | Community guidelines page top/bottom padding |

Exceptions: All interactive elements (report button, ban/unban button, mark reviewed button) minimum 44px height (WCAG 2.5.5). Modal dialog minimum 320px wide on mobile.

Source: Established in Phase 5 UI-SPEC. Exceptions: WCAG 2.5.5 touch target standard.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (text-base) | 400 (regular) | 1.6 |
| Label | 14px (text-sm) | 400 (regular) | 1.5 |
| Heading | 20px (text-xl) | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Notes:
- Body line-height 1.6 matches `globals.css` override — unchanged from prior phases.
- Admin dashboard stat numbers (pending reports count, ban count, new user count) render at Display size (28px semibold) to give quick visual scanning weight.
- Admin table column headers use Label size (14px) at weight 600 — same badge-exception pattern as Phase 5.
- Report status badges (Pending, Reviewed) use Label size (14px) at weight 600.
- Community guidelines section headers use Heading size (20px semibold).
- Soft-delete placeholder text uses Body size (16px) at weight 400, in `text-muted-foreground`, italic.
- Forum banner body copy uses Label size (14px) at weight 400.

Source: Established in Phase 5 UI-SPEC (`05-UI-SPEC.md`). Phase 6 additions noted above.

## Page Inventory

### `/admin` — Admin Dashboard

Layout: two-column on desktop (narrow left nav + main content), single-column on mobile. Left nav: 240px fixed, links to all four admin pages. Main content: padding lg (24px), max-width 960px.

Sections:
1. **Stats row** — three stat cards side by side (flex row, gap md). Each card: white background, border-border, rounded-lg, padding md. Stat number at Display (28px semibold), label at Label (14px muted). Cards: "Pending Reports" (count, links to /admin/reports), "Banned Users" (count, links to /admin/users), "Total Users" (count).
2. **Quick links** — three Button (outline variant) links to sub-pages below the stat cards.

### `/admin/reports` — Report Queue

Layout: full-width table within admin shell. Default view: Pending reports. Toggle button "Show All" / "Show Pending" top-right of table header row.

Table columns: Target (thread/post label + truncated title, links to target), Reported By (username), Reason (Badge default), Date, Status (Badge: Pending = default variant, Reviewed = secondary/muted variant), Actions.

Actions column per row: "Mark Reviewed" Button (primary, sm) — disabled if already Reviewed. Inline "Delete Content" Button (destructive, sm, outline). Inline "Ban User" Button (destructive, sm, outline). All three actions are Server Action form submissions with `pending` state (button disabled during submission).

Empty state: "No pending reports. The queue is clear."

### `/admin/users` — User Management

Layout: full-width within admin shell. Search input at top (full-width, placeholder "Search by username or email…"). Table below.

Table columns: Username, Email, Credential, Joined, Status (Badge: Active = default, Banned = destructive), Actions.

Actions per row: "Ban" Button (destructive, sm, outline) if not banned. "Unban" Button (outline, sm) if banned. Confirmation: inline optimistic update — no modal confirmation (solo operator tool, mistakes recoverable).

### `/admin/content` — Soft-Deleted Content

Layout: full-width within admin shell. Two tabs: "Removed Threads" | "Removed Posts". Tab uses Base UI Tabs if available, otherwise styled toggle buttons.

Table columns (threads): Title, Category, Author, Removed Date, Actions. Table columns (posts): Excerpt (line-clamp-2), Thread, Author, Removed Date, Actions.

Actions per row: "Restore" Button (outline, sm) — re-sets `is_removed = false`. "Delete Permanently" Button (destructive, sm) — requires a second confirmation click (inline: button text changes to "Confirm Delete" on first click, reverts after 3s if no action).

### `/community-guidelines` — Public Guidelines Page

Layout: single-column, max-width 720px, centered. No sidebar.

Sections (top to bottom, all with Heading 20px semibold headers):
1. **Introduction paragraph** — Body 16px, 2–3 sentences framing the clinical community purpose.
2. **De-identification & Patient Privacy** — key rules for clinical case discussions.
3. **Professional Conduct** — tone, credentials, respectful disagreement.
4. **Acceptable Content** — what belongs and what does not.
5. **Enforcement** — what happens when rules are violated (warning, removal, ban progression).
6. **Contact / Report** — how to flag content (links to report button on forum, contact email).

Footer of page: "Last updated: [date]" in Label muted.

Nav integration: linked in site footer (existing). Forum header banner (see GuidelinesBanner below) is the primary discovery mechanism during launch window.

## Interaction States

### Report Button

| State | Visual |
|-------|--------|
| Default (authenticated, not yet reported) | Ghost/outline icon button, Flag icon (lucide `Flag`, 16px), label "Report". Min height 44px. |
| Hover | Accent color (#0066cc) ring, Flag icon fills. |
| Already reported | Button disabled. Flag icon filled muted. Label "Reported". `aria-disabled="true"`. Tooltip on hover: "You've already reported this." |
| Own content | Button hidden. Authenticated user cannot report their own posts/threads. |
| Unauthenticated | Button hidden. |
| Submitting | Button disabled, spinner (Loader2, 16px, animate-spin) replaces icon. |

### Report Modal

| State | Visual |
|-------|--------|
| Open | Base UI Dialog centered overlay. Title: "Report this content" (Heading). Reason Select (required, no default selected, placeholder "Select a reason…"). Details Textarea (optional, max 500 chars, placeholder "Any additional context? (optional)"). Submit Button (primary, full-width). Cancel text link below. |
| Submitting | Submit button disabled, text "Submitting…". Form fields disabled. |
| Success | Dialog content replaces with: checkmark icon (CheckCircle, 24px, accent color), "Report submitted. We'll review it." (Body, centered). "Close" Button (outline, full-width). Auto-close after 3s. |
| Error | Inline error below submit button: "Something went wrong. Try again." (destructive color). Submit button re-enables. |
| Duplicate (already reported, race condition) | Treated as success — same confirmation state shown. |

### Guidelines Banner (forum area)

| State | Visual |
|-------|--------|
| Visible | Full-width banner at top of forum content area (below site nav, above forum category list). Background: muted (oklch(0.97 0 0)). Left icon: BookOpen (lucide, 16px, muted-foreground). Text: "New here? Read our [Community Guidelines](link) before posting." (Label 14px). Right: "×" dismiss button (ghost, 24×24px, min touch 44px). |
| Dismissed | `localStorage.setItem('guidelines_banner_dismissed', '1')` on click. Component renders `null`. Never re-appears on subsequent navigations or sessions (until localStorage cleared). |
| Server-side render | Render banner visible by default (SSR can't read localStorage). Client hydration checks localStorage on mount and hides immediately if key is set. Use `useEffect` on mount — no flash for returning users beyond first paint. |

### Soft-Delete Placeholder (PostItem)

| State | Visual |
|-------|--------|
| Post removed | Replaces post body entirely. Border: `border border-border`. Background: `bg-muted`. Rounded: `rounded-lg`. Padding: md (16px). Text: "[This post has been removed by a moderator.]" (Body 16px, italic, text-muted-foreground). No author, no actions, no vote buttons. |
| Thread removed (category listing) | Row filtered out of listings server-side. Not shown to regular users. |
| Thread removed (direct URL, non-admin) | Thread detail Server Component calls `notFound()` — renders 404 page. |
| Thread removed (direct URL, admin) | Visible with a "Removed" Badge (destructive) next to title. Restore/delete actions shown. |

### Admin Action Buttons (Mark Reviewed, Ban, Delete)

| State | Visual |
|-------|--------|
| Idle | Button enabled per variant (primary for Mark Reviewed; destructive outline for Ban/Delete). |
| Pending (Server Action in flight) | Button disabled. Text changes to "Working…". No spinner — button width preserved. |
| Success | Row updates in place (status Badge changes, button changes or hides). No toast in admin panel — inline state is sufficient for solo operator. |
| Error | Inline text below button: "Action failed. Reload and try again." (destructive, text-sm). |

### Permanent Delete (two-step in /admin/content)

| State | Visual |
|-------|--------|
| Step 1 | Button: "Delete Permanently" (destructive outline, sm). |
| Step 2 (after first click) | Button text changes to "Confirm Delete" (destructive filled). After 3s with no second click, reverts to Step 1. |
| Confirmed | Row removed from table. Inline "Deleted." text appears briefly in the row before removal. |

## Accessibility

- Report modal: `role="dialog"`, `aria-modal="true"`, `aria-labelledby` pointing to title. Focus trapped within dialog while open (Base UI Dialog handles this natively). `Escape` key closes modal without submitting.
- Report button `aria-label`: "Report this post" or "Report this thread" — specific to target type. Disabled state: `aria-disabled="true"` + `title` attribute for tooltip text.
- Guidelines banner dismiss button: `aria-label="Dismiss guidelines banner"`.
- Admin tables: `<th scope="col">` on all column headers.
- All interactive elements minimum 44px height (`min-h-[44px]`).
- Destructive buttons: do not rely on color alone — "Delete Permanently" and "Ban User" use distinct labels to convey destructive intent.
- Soft-delete placeholder: `aria-live="polite"` not required — content is static after render. The italic style is supplemented by bracket notation `[…]` for screen readers that ignore font style.
